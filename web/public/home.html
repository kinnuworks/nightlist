The problem

The answers exist. They sit in systems that don't share an ID.

Screening one patient against one trial by hand takes most of an hour. A community clinic has hundreds of lung cancer patients and over a hundred open trials nearby, and both change every week.

By handPenberthy et al., 2012
45 to 56 minper patient, per trial, read and checked by a coordinator
  • The EHR, the lab system, medication orders, molecular reports and ClinicalTrials.gov are separate places to look, and the orders and reports are free text.
  • In advanced NSCLC, about half of potentially eligible patients are lost to gaps in biomarker testing (Sadik et al., 2022).

How it's built

The model reads trials. SQL reads patients.

Eight agents run each night in order. Each one writes what it did, to which target and how long it took, to a trace you can open on the Run page.

Watcher

Pulls the ClinicalTrials.gov snapshot and records what opened, changed or closed in the World Model.

Guard

Runs Scout Intent on trial text before any model sees it. The compiler proceeds only on a signed contract for that one criterion.

Compiler

Turns each eligibility sentence into a typed check, by rule first and by model through Nightshift when rules cannot. Every output is validated against the schema.

Checker

A second model restates each compiled check in plain words. If it disagrees with the sentence, the criterion goes to a person.

Steward

Runs the semantic layer's data-quality rules. Lab rows with no matching patient or no unit stay out of screening.

Screener

One SQL pass per trial evaluates every check for every patient and returns met, not met or unknown.

Verifier

Re-reads the source rows behind each open match and sends it back when reports conflict, for example tissue and plasma KRAS.

Navigator

Applies remembered coordinator decisions from H-MEM, records the verdicts and writes the morning worklist.

The trace

Every step is logged with the agent, the target, the model that served the request and the duration.

Data layer

Zetaris

Six sources with no shared identifiers, queried in place. The trialmatch semantic layer joins them, and six data-quality rules run every night.

Engines and runtime

Meterless

World Model for what changed, H-MEM for coordinator notes, Scout Intent to guard trial text. Each passes the official suite. Nightshift is the model runtime.

Models

NVIDIA Nemotron

Served through Meterless Nightshift to compile the criteria rules cannot express and to check those compilations.

The model only sees public trial text. Patient rows are touched only by SQL generated from a validated check.

Questions

What it does and doesn't do.

Does Nightlist decide who can enroll?

No. It never says a patient is eligible. Each patient and trial pair lands in one of four groups: no blockers found, key criterion needs a human read, open items, or blocked. A coordinator and the trial team make the call.

Does the model see patient records?

No. The model reads public trial text and nothing else. Patient rows are touched only by SQL that code generates from a validated check, so the design holds even when the model runs in the cloud.

Where does the data come from?

Trials come from a ClinicalTrials.gov snapshot: 471 recruiting NSCLC trials with a US site, 106 of them within 250 miles of the demo clinic in Montgomery, Alabama. The clinic is River Region Cancer Care (fictional), and its 240 patients are synthetic, generated from published NSCLC figures. No real patient data is used.

How accurate is the compiler?

Real criteria were labeled blind and every compiled check was run against all 240 patients. A criterion counts as correct only when every patient gets the gold verdict. On the final sample, scored once, the rule compiler got 83.8% of the criteria it compiled right and compiled 84.7% of the criteria that can be compiled. What it cannot express goes to a person.

What runs where?

Zetaris is the data layer: the EHR, the lab system files and terminology services are registered there and queried in place through the trialmatch semantic layer. Model calls go through Meterless Nightshift to NVIDIA Nemotron. In sample mode the same semantic-layer SQL runs in an embedded DuckDB on your machine.

Can I run it myself?

Yes. You need Node 20 or newer and no accounts, keys or Docker. Clone the repository, then run npm ci, npm run build -w web, npm run demo and npm start, and open localhost:8787.
